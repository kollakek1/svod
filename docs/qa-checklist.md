# Приёмка СВОД

Проверяется на локальном dev-сервере `http://localhost:3001` и на собранной версии (`npm run build && npm start`).
Скриншоты — в `.artifacts/qa/`, отчёт — в конце.

## 1. Сборка

- [ ] `npm run typecheck` — 0 ошибок.
- [ ] `npm run lint` — 0 ошибок, 0 предупреждений.
- [ ] `npm test` — все тесты зелёные.
- [ ] `npm run build` — успешно, без предупреждений о hydration.
- [ ] В консоли браузера на `/` нет ошибок и предупреждений React.
- [ ] Нет `TODO`, `any`, `@ts-ignore`, `console.log` в `src/`.

## 2. Ширины

На 360, 390, 768, 1024, 1440, 1920:

- [ ] Нет горизонтального скролла (`document.documentElement.scrollWidth <= innerWidth + 1`).
- [ ] Заголовки не обрезаны и не наезжают на другие блоки.
- [ ] Кнопки не меньше 44px по высоте, текст не обрезан.
- [ ] Изображения не растянуты, пропорции сохранены.
- [ ] Первый экран: видно, что продают, цену первого визита и кнопку записи.

## 3. Запись (главный сценарий)

1. Открыть `/`, нажать «Записаться на приём».
2. Выбрать услугу «Лечение кариеса под микроскопом».
3. Выбрать врача (только те, кто выполняет услугу).
4. Выбрать дату и время из слотов, которые вернул сервер.
5. Заполнить имя, телефон, согласие; отправить.
6. Получить код `SVD-XXXX` и увидеть услугу, врача, дату, цену.

Проверить:
- [ ] Шаг нельзя пропустить без выбора; назад — данные сохранены.
- [ ] Смена услуги сбрасывает врача и время.
- [ ] Телефон форматируется маской, ошибка появляется на blur.
- [ ] Согласие обязательно; ссылка ведёт на `/privacy`.
- [ ] Двойной клик по «Записаться» не создаёт две брони.
- [ ] После успеха фокус на заголовке, есть «Записать ещё».
- [ ] Занять слот в другой вкладке и отправить тот же — получить 409, вернуться на шаг времени,
      выбранное время сброшено, бронь не создана дважды.
- [ ] Клавиатурой можно пройти все 4 шага.

## 4. Админка

- [ ] `/admin` без входа ведёт на `/admin/login`.
- [ ] Неверный пароль — одна человеческая ошибка, без подсказок.
- [ ] Верный вход — календарь текущего месяца.
- [ ] Бронь из шага 3 видна в календаре и в дне; телефон и комментарий видны.
- [ ] «Подтвердить» → статус меняется, история пополняется.
- [ ] «Принять» → статус «Принята».
- [ ] Создание услуги: появляется в таблице, на сайте в секции услуг и в шаге 1 записи.
- [ ] Правка цены: новая цена на сайте и в записи.
- [ ] Удаление услуги без броней — работает.
- [ ] Удаление услуги с будущей бронью — блокируется, показывает список броней.
- [ ] Выход — сессия закрыта, `/admin` снова требует вход.
- [ ] `/admin` и `/admin/login` отдают `noindex`.

## 5. Служебные страницы

- [ ] `/privacy` открывается, текст читается, ссылки из футера и формы ведут сюда.
- [ ] `/несуществующая` — брендовая 404, статус 404, есть «На главную» и «Записаться».
- [ ] Ошибка рендера — человеческий текст, без стектрейса и digest (проверить временным throw).
- [ ] `global-error` не показывает внутренние пути.
- [ ] Телефон, адрес и часы доступны с мобилы из футера.

## 6. SEO и метаданные

- [ ] `/icon.svg` 200, знак читается на 16px.
- [ ] `/apple-icon.png` 200, 180×180.
- [ ] `/manifest.webmanifest` 200, `theme_color` = фон.
- [ ] `/opengraph-image` 1200×630, кириллица корректна.
- [ ] `title`, `description` (≤160), `canonical`, `og:*`, `twitter:card`.
- [ ] `/robots.txt` 200, закрывает `/admin` и `/api`, ссылается на sitemap.
- [ ] `/sitemap.xml` 200, содержит `/` и `/privacy`, без админки.
- [ ] JSON-LD валиден (schema.org validator), содержит `Dentist`, услуги с ценами, FAQ.
- [ ] Один `<h1>`, иерархия заголовков без пропусков, `lang="ru"`.

## 7. Доступность и движение

- [ ] Tab по странице: фокус всегда виден, порядок логичный.
- [ ] Меню на мобиле: открывается, закрывается Esc, фокус возвращается.
- [ ] Аккордеон FAQ: работает мышью и клавиатурой.
- [ ] Маркиза отзывов останавливается кнопкой и на hover.
- [ ] `prefers-reduced-motion: reduce`: нет маркизы, параллакса, появлений; весь контент виден.
- [ ] Контраст текста ≥ 4.5:1 (проверить хотя бы muted на bone и на ink).
- [ ] Формы: label связан с полем, ошибки в `aria-live`, `aria-invalid` выставлен.

## 8. Производительность

- [ ] Lighthouse mobile на `/`: performance ≥ 85, accessibility ≥ 95, SEO ≥ 95.
- [ ] LCP < 2.5 s, CLS < 0.1, INP < 200 ms (в Lighthouse/DevTools).
- [ ] Нет изображений без width/height.
- [ ] Основной JS-бандл без тяжёлых неиспользуемых библиотек.
- [ ] Шрифты: `display: swap`, не более нужных начертаний.

## 9. Данные

- [ ] Перезапуск dev-сервера не теряет брони и правки каталога.
- [ ] Коды броней уникальны.
- [ ] В публичном API нет телефонов и комментариев пациентов.
- [ ] `GET /api/catalog` и `/api/availability` не кешируются браузером.
