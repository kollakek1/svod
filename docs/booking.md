# Запись: поведение и состояния

Компонент: `src/components/booking/booking-form.tsx` (клиентский), встраивается в секцию `#booking`.
Данные каталога приходят пропсами (`services`, `doctors`) со страницы. API — `docs/architecture.md` §4.

## 1. Шаги

```
01 Услуга → 02 Врач → 03 Время → 04 Контакты → Успех
```

- Stepper: `<ol>`; пройденные шаги — кнопки, будущие — `aria-disabled`; текущий `aria-current="step"`.
- Прогресс 2px `accent-text`, `scaleX(step/4)`.
- Возврат назад не теряет выбор. Вперёд — только при валидном выборе (кнопка disabled).
- Смена услуги сбрасывает врача и время. Смена врача сбрасывает время.

## 2. Шаг 1 — услуга

- Группы по категориям, заголовок группы — mono.
- Строка: радио + название + summary + длительность + цена.
- `<fieldset>` + `<legend class="sr-only">Услуга</legend>`, нативный `input[type=radio]` визуально скрыт,
  карточка реагирует на `:has(:checked)` и `:focus-visible`.
- Предвыбор из события `svod:book-service` (`{ serviceId }`).
- Цена «от» — как в каталоге; итог в summary показывает «от …».

## 3. Шаг 2 — врач

- Только врачи, выполняющие услугу (`service.doctorIds`).
- Карточка: фото (если есть), имя, роль, стаж, ближайший рабочий день текстом.
- Один врач в списке — всё равно показываем шаг (человек должен видеть, к кому идёт).
- Клик — выбор, кнопка «Далее».

## 4. Шаг 3 — дата и время

- Запрос: `GET /api/availability?serviceId=…&doctorId=…&days=21`.
- Дата-лента: горизонтальный скролл на мобиле, сетка 7×3 на десктопе. Каждая дата: день недели, число,
  количество слотов или «—». Дни без слотов `disabled`.
- Слоты: группы «Утро 09:00–12:00», «День 12:00–17:00», «Вечер 17:00–21:00», сетка 4/3 колонки, высота 48.
- Loading — 6 скелетонов. Error — «Не удалось загрузить окна» + «Повторить».
- Empty — «На этот день окон нет» + две ближайшие даты со слотами кнопками.
- Выбор слота сохраняется как ISO-строка ровно из ответа (не собирать на клиенте).
- Перед переходом на шаг 4 — проверка, что слот ещё в списке; если нет — сообщение и обновление.

## 5. Шаг 4 — контакты

Поля:
- Имя (autocomplete name), 2–80.
- Телефон (autocomplete tel, inputmode tel, маска `maskPhone` на вводе).
- Email (необязательно, type email).
- Комментарий (textarea, ≤ 500, счётчик не нужен).
- Согласие: чекбокс + «Согласен с [политикой конфиденциальности](/privacy)».
- Honeypot: `name="website"`, `tabIndex={-1}`, `autoComplete="off"`, спрятан за пределами экрана.
- `formStartedAt` — `Date.now()` в момент монтирования шага 4.

Валидация: на blur и на submit; ошибка под полем + `aria-invalid` + `aria-describedby`.
Общая ошибка — в `aria-live="polite"` над кнопкой. Кнопка блокируется на время запроса (`aria-busy`).

## 6. Отправка

`POST /api/booking` с полями из контракта.

| Ответ | Что делает UI |
| --- | --- |
| 201 | экран успеха: код, услуга, врач, дата/время, цена, кнопка «Записать ещё», фокус на заголовок |
| 409 | «Это время только что заняли», сброс времени, возврат на шаг 3, обновление слотов |
| 422 | подсветка полей, текст ошибки |
| 429 | «Слишком много попыток. Позвоните нам — …» |
| 5xx/сеть | «Не удалось отправить. Проверьте связь и попробуйте снова», данные не теряются |

Повторная отправка невозможна: кнопка disabled до ответа, состояние `submitting`.

## 7. Summary

- Десктоп: справа, `sticky top: 96px`, до 416px, рамка 1px, padding 24–28.
- Строки: услуга, врач, дата, время, итог. Пустые — «не выбрано» muted.
- Ниже: «Оплата после приёма. Отмена — за 6 часов», ссылка на политику.
- Мобайл: бар над формой, свёрнут в одну строку (услуга · время · цена), кнопка «Детали» открывает Dialog.

## 8. Интеграция

- Слушать `svod:book-service` и `svod:book-doctor` на `window`; при событии — выбрать и прокрутить к секции.
- Секции вызывают `selectServiceForBooking` / `selectDoctorForBooking` из `src/lib/booking-events.ts`.
- После успешной записи отправить событие `svod:booked` (для аналитики в будущем).

## 9. Доступность и мобилка

- Все контролы ≥ 44px. Клавиатурный проход по всем шагам.
- Фокус при смене шага переводится на заголовок шага (`tabIndex={-1}`).
- Ошибки не только цветом: текст + иконка.
- На 360 сумма и кнопка «Далее» всегда достижимы без горизонтального скролла.
