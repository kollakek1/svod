### Сквозные сценарии

- Смоук на проде (`scripts/smoke.mjs`): каталог → слоты → бронь 201 → публичная карточка без телефона →
  повтор на слот 409 → вход в админку → подтверждение → создание/удаление услуги → выход. Все 16 проверок ok.
- Запись через UI: услуга → врач → время → контакты → успех с кодом; цена «от» для услуг с плавающей ценой.
- Админка: вход, календарь с количеством записей (включая завершённые), день, карточка брони,
  статусы, заметка; каталог: правка услуги видна на сайте, удаление услуги с будущей бронью блокируется.
- Ширины 360 / 390 / 768 / 1024 / 1440 / 1920: горизонтального скролла нет, контент не обрезается.
- `/privacy` и 404 отдают 200 и 404 соответственно; ссылки из футера и формы ведут на политику.
- `prefers-reduced-motion`: маркиза статична, все блоки видимы.
- SEO: canonical, OG 1200×630 с кириллицей, `robots.txt`, `sitemap.xml`, JSON-LD (`Dentist`, 10 услуг, FAQ).
  Админка закрыта от индексации.

### Данные на проде

- Демо-записи: 8 броней на 23–27 ноября 2026 с разными статусами, перенесены в Postgres
  (`scripts/seed-demo-postgres.mjs`).
- Владелец: `owner@svod.dental`; имя в интерфейсе — Анна Ковалёва. Пароль выдан отдельно,
  в репозитории его нет. Сменить: обновить `ADMIN_PASSWORD` в Vercel, удалить документ `admins`
  в базе (или создать нового владельца) и войти заново.

## Известные ограничения

- Фотографии сгенерированы для макета, врачи и отзывы вымышлены — заменить перед публикацией
  (см. `public/images/CREDITS.md`).
- Управления сотрудниками в UI нет: роли `owner`/`manager` и гарды есть в коде, экранов — нет.
- Гонка «удаление услуги ↔ новая бронь» закрыта не полностью: нужен общий advisory-lock на каталог
  и брони. При одном администраторе не проявляется; описано в `docs/code-review-fixes.md`.
- Аналитики нет — по политике проекта подключается только по запросу и с согласием.
- Политика конфиденциальности — шаблон, требует проверки юристом и реальных реквизитов.
