# Демонстрация СВОД

Короткий сценарий показа: что открыть, в каком порядке и что должно произойти.

## 1. Витрина

1. `/` — первый экран: обещание, две кнопки, часы, адрес, цена первого визита.
2. Прокрутить: манифест → приём → услуги с ценами → программы → врачи → клиника (схема FDI) →
   случаи → отзывы → вопросы → запись.
3. Проверить на узком экране (390): меню, услуги, карточки врачей, запись.

## 2. Запись

1. «Записаться на приём» → выбрать услугу.
2. Врач: список ограничен теми, кто выполняет услугу.
3. Дата и время: слоты приходят с сервера; занятые не показываются.
4. Контакты: имя, телефон, согласие. Отправить.
5. Экран успеха: код `SVD-XXXX`, услуга, врач, дата, цена.

Проверка конфликта: занять слот в соседней вкладке (или через `POST /api/booking`) и отправить
ту же форму — форма вернётся на шаг времени и сбросит выбранный слот.

## 3. Админка

- `/admin/login` — почта и пароль владельца. Значения лежат в `.env.local` (в репозиторий не попадают).
- `/admin` — календарь месяца с числом записей, день с записями, карточка брони:
  телефон, комментарий, история, статусы «Подтвердить / Принять / Отменить / Не пришёл», заметка.
- «Каталог» — правка услуги: название, категория, длительность, цена, врачи. После сохранения
  изменение видно на сайте и в шаге 1 записи.
- Попытка удалить услугу с будущей бронью — отказ со списком записей.

## 4. Служебное

- `/privacy` — политика конфиденциальности, ссылки из футера и формы.
- `/no-such-page` — брендовая 404 со статусом 404.
- `/robots.txt`, `/sitemap.xml`, `/opengraph-image` — SEO-файлы.
- Ошибка рендера проверяется временным `throw` в серверном компоненте: экран должен быть
  человеческим, без стектрейса и `digest`.

## 5. Сброс демо-данных

```bash
node scripts/seed-demo-bookings.mjs
```

Скрипт перезаписывает `.data/bookings.json` восемью записями на 23–27 ноября 2026.
Каталог сбрасывается удалением `.data/catalog.json` — при следующем запросе он создастся из
`src/content/clinic.ts`.

Вход в админку: удалить `.data/admins.json` — владелец создастся заново из `ADMIN_EMAIL` и
`ADMIN_PASSWORD` при первом входе.

## 6. Ограничения демо

- Данные файловые: после холодного старта на serverless их не будет. Для прода — `DATABASE_URL`.
- Rate limit в памяти процесса: при перезапуске сбрасывается.
- Фотографии сгенерированы, врачи и отзывы вымышлены. Перед публикацией — заменить (см. `public/images/CREDITS.md`).
- SMS-подтверждения нет: запись подтверждает администратор звонком.
