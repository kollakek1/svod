# Админка: сценарии и экраны

Цель: сотрудник без инструкции понимает, что делать. Никаких технических формулировок про сессии и cookie.

## 1. Вход `/admin/login`

- Логотип, заголовок «Вход в кабинет», поля «Почта» и «Пароль», кнопка «Войти».
- Ошибка одна: «Почта или пароль не подошли». Без подсказок, существует ли аккаунт.
- Rate limit: после 429 — «Слишком много попыток. Подождите 15 минут».
- После входа — `/admin`. Если сессия истекла — возврат на вход с сообщением «Войдите снова».
- `metadata`: `robots: { index: false, follow: false }` на `/admin/layout.tsx`.

## 2. Каркас `/admin`

- Шапка: логотип, имя сотрудника, роль, «Выйти». Высота 64, линия снизу.
- Навигация: «Календарь» и «Каталог». Активный раздел подчёркнут.
- Контент — на светлом фоне, плотная сетка, шрифт Golos, числа `tnum`.
- Мобайл: навигация — две вкладки под шапкой, таблицы превращаются в карточки.

## 3. Календарь (главный экран)

- Месяц: сетка 7 колонок, дни с числом и количеством записей. Сегодня — рамка, выбранный — заливка `ink`.
- Стрелки ‹ › и кнопка «Сегодня».
- Под календарём (или справа на ≥1280) — день: список записей по времени.
- Карточка записи в списке: время, имя, услуга, врач, статус (цветной текст, не плашка).
- Пустой день: «На этот день записей нет» + «Добавить запись».
- Ошибка загрузки: текст + «Повторить». Loading — скелетоны строк.

### Карточка брони (панель справа или диалог)

- Код `SVD-XXXX`, статус, время и длительность, услуга и цена, врач.
- Пациент: имя, телефон (ссылка `tel:`), email, комментарий.
- Действия: «Подтвердить», «Принять», «Отменить», «Не пришёл». После действия — перезапрос данных.
- Заметка сотрудника (textarea) с кнопкой «Сохранить заметку».
- История: время, кто, что изменил.

## 4. Добавление записи

Диалог: услуга → врач → дата (14 дней) → время (слоты из API) → имя и телефон.
Цена и длительность — с сервера. После создания — открыть карточку новой брони.

## 5. Каталог

Две вкладки: «Услуги» и «Врачи».

**Услуги** — таблица: название, категория, длительность, цена, врачи. Кнопки «Изменить» и «Удалить».
Диалог редактирования: название, категория (select), summary, описание, длительность (15–480), цена,
переключатель «от», чекбоксы врачей. Валидация — под полями.

**Врачи** — таблица: имя, роль, стаж, рабочие дни. Диалог: имя, роль, focus, стаж, рабочие дни (чипы),
фото (необязательно, путь). Удаление врача, который ведёт услуги, блокируется с объяснением.

Удаление услуги с будущими бронями: диалог «Нельзя удалить: есть 2 будущие записи» + список
(код, дата, пациент) + «Закрыть». Никаких «архивировать».

## 6. Состояния и доступность

- Все мутации: кнопка блокируется, ошибка рядом, после успеха — перезапрос.
- Диалоги: focus trap, Esc, возврат фокуса на триггер.
- Таблицы: `<table>` с `th[scope]`, либо список карточек с заголовками; клавиатура работает.
- Никаких `window.alert`/`confirm` — только диалоги в стиле сайта.
- Мобилка 360: всё читается, ничего не уезжает вправо.
